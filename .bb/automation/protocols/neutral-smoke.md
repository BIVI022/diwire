# Neutral pipeline smoke check

This protocol checks measurement execution and rejection behavior. It does not
propose a DIWire runtime optimization.

The candidate and baseline must have identical src/diwire trees. Run the frozen
public transient-resolution target and singleton-resolution control on pinned
Linux CPython. Retain three fresh baseline calibrations and five alternating
pairs, with all raw rounds and source/runtime binding receipts.

A five percent throughput floor is deliberately above zero for this neutral smoke check; identical source must never be accepted as an optimization.

The spread ceiling is a test environment check. A noisy hosted run can be
inconclusive, but cannot become an accepted speed claim. This setup smoke uses
a 10 percent ceiling and a fixed two percent protected-regression limit. These
values apply only to this neutral execution check. Future optimization jobs
must declare workload-specific rules and rationale before timing.

Expected outcome: rejected for identical library source, or inconclusive if the
runner is unstable. An execution error means setup is not verified. This check
must run all declared processes and retain binding, raw data and final decision.
A valid neutral rejection alone makes no claim about sensitivity to real gains.
