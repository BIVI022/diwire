## Socket HTTP protocol

Use `tests.performance.one_positional_socket` from the same frozen harness in
both archived subject trees. Put each subject's `src` and archive root first on
PYTHONPATH. Use the same locked interpreter and dependencies as the timing run.
Run each subject from its own archive root. Record full SHAs, source and harness
hashes with the controller receipt before launching the module:

```sh
PYTHONHASHSEED=0 uv run --locked python -m tests.performance.one_positional_socket \
  --subject-root "$SUBJECT_ARCHIVE_ROOT" --output "$UNIQUE_SOCKET_OUTPUT"
```

The fixed setup uses one Uvicorn worker, asyncio, h11, loopback TCP, eight HTTPX
clients in flight, 1,000 warmup requests and 30,000 measured requests per route.
It measures `/control`, `/consumer` and `/resource` in that order. Setup, readiness,
shutdown and status checks are outside request timing. Retain warmup results and
all request latencies, errors, bodies that fail validation, server logs and source
bindings. Require exact 200 bodies `{"ok":true}`, zero errors and exactly 31,000
opened and closed resource scopes. Require a clean server shutdown.

Run three fresh baseline calibrations, then five alternating fresh-server pairs.
Use the same counts for every process. No concurrent benchmark or quality work.
For every route require calibration and role throughput/p95 spreads <=5%.
For every pair require throughput loss <=2% and p95 growth <=2%. An effect
range across a loss boundary is inconclusive; a range wholly beyond it rejects.
An HTTP gain claim also needs median throughput gain >1%, above baseline
throughput spread, and every pair positive. The 1% floor avoids presenting tiny
request differences as useful gains. A resolver gain does not require an HTTP
gain. Report negligible or uncertain HTTP effects as such.

For HTTP and memory, compute each process metric from its complete saved record.
For any series, spread is `(max - min) / median`, with separate calibration,
baseline and candidate series. For each BC pair compute throughput gain as
`B_rps / A_rps - 1`, throughput loss as `1 - B_rps / A_rps`, p95 growth as
`B_p95 / A_p95 - 1`, and byte growth as `B_bytes / A_bytes - 1`. Here A is
baseline and B is candidate, regardless of run order. Use the median of the
five paired effects and their full min/max range. An interval wholly within
the budget passes, wholly beyond it rejects, and across it is inconclusive.
Any unstable series makes the campaign inconclusive. Never pool route results.
Retain the calculation script and all inputs with the final receipt. The
controller must bind expected full SHAs, archive hashes and lock hash before
launch. A zero or missing metric is an error. All harnesses must pass an
independently specified `--subject-root`; imported package paths cannot define
the expected subject. Record all source file hashes before and after each run.
